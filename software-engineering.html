Software Engineering

A compact guide to requirements, design, testing and maintenance.

5 topics · Requirements, UML and testing

SE 01Requirements Engineering

Functional requirements describe behavior. Nonfunctional requirements state constraints or quality targets such as latency, reliability, and accessibility. Make them measurable.

Vague: "The app is fast."
Testable: "95% of searches finish within 2 seconds."

Quick check: Is an audit log a functional requirement or a quality constraint?

SE 02Development Models

Waterfall separates phases; iterative development revisits a product in increments; agile practices emphasize frequent feedback. Choose based on uncertainty, risk, and release needs.

Plan → Build → Evaluate → Adapt → next iteration

Quick check: Why is early feedback useful when requirements are uncertain?

SE 03UML & Software Design

Use case diagrams show actors and goals, class diagrams show structure, and sequence diagrams show messages over time. Design for clear responsibilities and low coupling.

Client → OrderService: placeOrder()
OrderService → Inventory: reserve()

Quick check: Which diagram best shows a time-ordered interaction?

SE 04Testing & Coverage

Unit tests check components; integration tests check interfaces; system tests exercise the whole product. Statement coverage measures executed statements and does not prove correctness.

Coverage = executed statements / total statements × 100%

Quick check: Can 100% statement coverage miss an incorrect boundary condition?

SE 05Maintenance & Configuration

Maintenance includes corrective, adaptive, perfective, and preventive work. Version control records changes; code review and automated tests reduce regression risk.

Issue → change → review → test → release

Quick check: Is updating software for a new operating system adaptive or corrective maintenance?
